# runadops.com · 操盘控制台 — 部署与运维手册

> 推广代运营 · 操盘控制台(团队版) · 交接文档
> 生成于 2026-11-19 · 存着随时查,不用记

**一句话**:`https://runadops.com` 是团队内部用的操盘控制台(管客户、投放配置、投放项目、收款、套餐)。全员各自账号登录,看同一套数据。前端放在你自己的 Vultr 服务器(nginx),数据存在 Supabase 云数据库。

## 3 · 收尾:接上 Supabase(最后一步)

1. **建项目**:到 `supabase.com` 注册、New project(免费)。
2. **建表**:左侧 SQL Editor → New query → 粘贴第 6 节脚本 → Run。
3. **拿密钥**:Project Settings → API → 复制 `Project URL` 和 `anon public` key。
4. **填进 config**(在服务器上改,不用下载):
   ```bash
   ssh root@139.180.210.215
   nano /var/www/runadops/config.js
   # 把两行占位换成你的 URL 和 anon key
   # 存盘 Ctrl+O 回车,退出 Ctrl+X
   ```
5. **刷新** `https://runadops.com`(Ctrl+F5)→ 出现登录页 → 邮箱**注册**(第一个=owner)→ 进「投放配置」点「载入预设」。
6. 注册完 owner,回 Supabase → Authentication → 关掉公开注册,之后用邮箱邀请队友。

## 4 · 日常运维

**更新控制台(换新版 index.html)** — 刷新网页即生效,无需重启:
```bash
scp "新文件路径\xxx.html" root@139.180.210.215:/var/www/runadops/index.html
```

**加 / 管理团队成员**
- 加人:Supabase → Authentication → Users → Add user / Invite 邮箱邀请。
- 改角色(owner/admin/member):Supabase → Table Editor → `profiles` 表 → 改 `role`。
- 权限:owner/admin 能删数据,member 只能增改(防手滑)。

**备份数据**
- 控制台左下角「备份」按钮 → 随时导出 JSON 存档。
- Supabase 本身每日自动备份。

**SSL 续期** — certbot 自动续,不用管。手动验证:`certbot renew --dry-run`。

## 5 · 出问题怎么查

| 现象 | 处理 |
|---|---|
| 打开是别的页(如 CallDesk) | `/var/www/runadops/index.html` 传成了错文件。重新把正确控制台 html(约 46KB,开头 `<html lang="zh-CN">`)scp 覆盖。核对:`head -3 /var/www/runadops/index.html` |
| 黄色"还没配置后端" | `config.js` 里 Supabase URL/key 没填或填错。`nano` 改,刷新。 |
| 登录报错 / 没数据 | Supabase 建表脚本没跑成功,或 URL/key 填反。重跑第 6 节脚本。 |
| 网页打不开 | SSH 上 `nginx -t`、`systemctl status nginx`;`ping runadops.com` 确认 DNS 指向 215。 |
| 传文件老传错 | 先确认文件真在电脑上:`Get-ChildItem $HOME\Downloads -Filter *.html`;用唯一文件名。 |

## 6 · 建表脚本(Supabase SQL Editor 跑一次)

```sql
create table if not exists public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  email text, name text, role text not null default 'member',
  created_at timestamptz default now()
);
create table if not exists public.records (
  id uuid primary key default gen_random_uuid(),
  type text not null, data jsonb not null default '{}',
  updated_at timestamptz default now(), updated_by uuid
);
create index if not exists records_type_idx on public.records(type);
alter table public.profiles enable row level security;
alter table public.records enable row level security;
create policy "profiles_read" on public.profiles for select to authenticated using (true);
create policy "profiles_insert_self" on public.profiles for insert to authenticated with check (auth.uid() = id);
create policy "profiles_update_self" on public.profiles for update to authenticated using (auth.uid() = id);
create policy "records_all_auth" on public.records for all to authenticated using (true) with check (true);
alter publication supabase_realtime add table public.records;
alter publication supabase_realtime add table public.profiles;
create or replace function public.handle_new_user()
returns trigger language plpgsql security definer set search_path = public as $$
declare cnt int;
begin
  select count(*) into cnt from public.profiles;
  insert into public.profiles(id,email,name,role)
  values (new.id,new.email,split_part(coalesce(new.email,'user'),'@',1),
          case when cnt=0 then 'owner' else 'member' end)
  on conflict (id) do nothing;
  return new;
end; $$;
drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created after insert on auth.users
  for each row execute procedure public.handle_new_user();
```

## 7 · 安全提醒

- `config.js` 里的 **anon key 可公开**(安全靠数据库 RLS),但**绝不要**把 Supabase 数据库密码、`service_role` key 放进前端。
- 注册完 owner,**关掉 Supabase 公开注册**,只邀请团队。
- 服务器 root 密码、Supabase 登录,存自己的密码管理器,别写进本文档。
